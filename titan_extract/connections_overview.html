§2 · Money / ledger resolution (where does the money actually live?)

Headline: there are no wzmony / wzdaily / wzbank SQL tables. The docs use those names as conceptual shorthand; the real money store is (a) the farysales SQL ledger and (b) the serialized .phy daily files.

2.1 The drawer (الدرج) model — cash / شبكة / أجل splits

Every invoice splits totalvalue = payed (cash + visa/شبكة) + agel (credit/أجل) (feature_sales_invoices.md:153, idx 13344).

SideSourceEffect on drawer
Cash salesales invoice, payed cashin (قبض) — drawer up
Card / شبكة salepayed visa portionnot drawer; شبكة balance
Credit / أجل saleagel portionnot drawer; customer debt up (wzcustomers)
Cash returnsales returnout — خروج نقدية نتيجة ارتجاع (idx 11421)
Cash purchasepurchase from drawerout — تخرج من الدرج
Supplier refundpurchase return refundedin — دخول نقدية نتيجة ارتجاع الدفع
Customer settlement (سند قبض)receivable paymentin
Supplier payment (سند صرف)payable paymentout
Expenses (مصروفات)حركة مالية screenout — must move drawer→treasury before close

Drawer accounting identity (three equivalent statements):

  • drawer = cash sales − cash returns + customer settlements (sales:338, idx 12675/8956)
  • expected drawer = current drawer − drawer@start + cash that left (closing:65, idx 8305)
  • Sales vs drawer: sell 2×500 and buy 300 of drugs → sales total 500, drawer only 200 — expenses don't reduce sales totals (closing:311, idx 8336/9963)

2.2 How transactions flow into farysales

farysales = SQL posting journal (accounting); .phy = cash/day register the close reconciles:

  • Sales cash/visa/أجل → day register (`.phy`) + titanksasales/invoicedata; أجل العملاء posts via wzcustomers (balances:132)
  • Purchases → credit (دائن) posting, father/son = خصوم.موردين, creditdebit='credit' (purchases:140-142)
  • Purchase returns → debit posting against the same account (purchase_returns:87,145)
  • Manual entries → daily-manual.phy/-2 + FormDailyManual2 via wzaccfreetree
  • Day close aggregates كاش/شبكة/مصروفات/مشتريات/ضريبة and rolls forward (closing:67,75,163)

§5 · Cross-feature flow narrative (end-to-end, plain language)

Purchased → Stocked → Priced → Sold → Returned → Counted → Short-flagged → Discounted → Taxed → Posted → Closed → Balanced → Archived → Reported → Synced → Exported.

  1. Purchased. A purchase invoice is the entry point of everything (first invoice must be a saved purchase, purchases:378). Opening stock (الجرد الاولي) is a special purchase.
